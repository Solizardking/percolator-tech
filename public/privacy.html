Categories of personal data collected

We collect only the categories below, and only when you use the corresponding feature. We do not ask you to paste seed phrases or private keys into these pages, and the Services are not designed to take custody of your keys.

  • Network and request logs. When you load a page or call an API, standard request metadata may be processed by our hosting providers (for example Cloudflare on percolator.tech, Render on percolator.musebook.trade, and the origin that serves percolator.clawdchain.trade). This typically includes IP address, date and time, URL or path, user-agent, referrer, and response status. Cloudflare and similar providers may also use this data for security, caching, and abuse prevention.
  • Public wallet addresses and on-chain identifiers. If you use trade, stake, or other wallet-connected flows, or you look up a position with an owner address, you may submit a public wallet address. Those addresses are public blockchain identifiers. The percolator.tech Worker also exposes GET /api/me, which verifies a Privy session token and returns a Privy user id and session id; it is written not to return secrets or private keys.
  • Optional install-telemetry (install.percolator.tech). Install pings may record a source label (skill, repo, template, agent, or test), optional agent id, version, and cluster, plus an HMAC-SHA256 hash of the client IP (the raw IP is hashed with a server-side salt and is not stored in the install record). Test-source events are excluded from public counts.
  • Public market and feed data. Endpoints such as /api/markets, /api/feed, and /ops-snapshot.json serve public market, feed, and operations data. The feed may call GitHub’s public API using a server-side token only to stay within rate limits; that token is not a user credential and is not shown to browsers.

We do not currently operate a general user-account database on percolator.tech (there is no live /api/auth sign-up). If account sign-in is added later, this policy will be updated before that collection starts.

Purposes

  • To operate, cache, and secure the websites and APIs, including health checks and abuse rate limits.
  • To show public market, feed, proof, and operations information.
  • To verify a wallet session you already created with Privy when you call /api/me, and to let you use wallet-connected testnet/devnet features on your own device.
  • To count optional skill or template installs without storing raw IP addresses.
  • To diagnose failures and keep the Services available.

Recipients

  • Hosting and edge. Cloudflare (percolator.tech Worker and DNS), Render (percolator.musebook.trade and, historically, an install-tracker service), and the origin host for percolator.clawdchain.trade.
  • Wallet session verification. Privy, when you use a Privy-issued token with /api/me or wallet-connected site features. Privy is a separate service with its own policy.
  • Public software metadata. GitHub, for public repository and Actions data used to build the feed.
  • Upstream market APIs. Public market data may be fetched from percolator.clawdchain.trade and shown on percolator.tech.

We do not sell personal data. We do not use the Services to take custody of user funds or keys.

Retention

  • Edge and origin request logs are retained according to each provider’s default logging windows unless a longer period is required for security or legal reasons.
  • Install records store an IP hash and event metadata. The current free-tier key-value store used for those events is ephemeral; we do not treat it as a permanent archive.
  • Public market, feed, and snapshot data are operational content, not a user profile store.
  • Privy session tokens are verified in request and are not stored by the percolator.tech Worker as a long-lived account database.

User controls

  • You can use the read-only pages and APIs without connecting a wallet.
  • You can disconnect your wallet in your wallet app or Privy session, and you can stop sending install pings by not running the optional install scripts.
  • Because wallet addresses are on a public chain, we cannot delete the chain itself. We can help review or delete install-telemetry records we control, where we can identify them.
  • To ask questions, object, or request access or deletion of data we hold, email toly@mail.grokbot.com.

Children

The Services are not directed at children, and we do not knowingly collect personal data from children.

Changes
